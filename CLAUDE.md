## Assistant behavior and interface

### Relevance protection layer

Lexcia adapts ArchiveLens’s structured relevance guard in `backend/lexcia/guard.py`. Both local and Vercel entry points run it before knowledge retrieval and answer generation. It uses the configured model with a non-streaming structured-output call, a 20-second timeout and no retries. `config/demo.yaml` sets the relevance threshold to 5 out of 10; routing enforces the score rather than trusting the returned boolean. Lexcia product questions, visitor-specific website fit, greetings and contextual follow-ups are in scope; unrelated tasks, prompt/secret extraction and rule overrides are rejected. Context is bounded to two completed turns, each message capped at 1,500 characters. Invalid classifications and provider failures stop the turn with a retry notice. Guard model tokens never enter the public stream; no retrieval, answer model, sources or generated follow-ups run on a stopped turn, and rejected requests do not enter server history. Logs contain decision metadata or exception type only, without question text or provider details. This is an LLM relevance gate, not a guarantee against every adversarial input.

The website mounts an adaptation of assistant-ui’s standalone [GuardrailNotice](https://www.assistant-ui.com/elements/guardrail-notice), preserving its shield/title/policy/explanation/alternatives structure with Lexcia’s paper and ochre styling. Off-topic notices offer useful Lexcia questions; selecting one submits it through the existing flow. Unavailable checks offer Try again for the original question, distinct from a scope rejection. English and Hebrew notices are supported. Scheduling remains a local form action and does not invoke the answer model. The backend remains independent of ArchiveLens.

### Follow-up suggestions

Follow-up suggestions (October 18, 2026): after the latest completed product answer, show assistant-ui runtime follow-ups using AuiIf, useAuiState, ThreadPrimitive.Suggestion send and the existing useExternalStoreRuntime. A React portal places wrapping paper-pill buttons below the transcript while sharing the welcome runtime. The LLM now generates 2–3 context-aware prompts and action types (ask or schedule_demo) in the same call as its answer. backend/lexcia/followups.py separates and validates the [[FOLLOWUPS]] JSON footer; AnswerStream hides metadata even across chunk boundaries. The final SSE event includes suggestions, saved with the frontend turn. There is no fixed list, local topic selection or extra model call. Invalid/missing metadata leaves the answer intact with no suggestions. Local code only validates/deduplicates prompts, hides suggestions while empty/running/failed/scheduling, and suppresses scheduling for open drafts or refusals. Model-selected language and wording are preserved. A schedule_demo action opens the existing pinned local preview even if the prompt is phrased differently from the old keyword trigger. No new backend endpoint or dependency is needed.

## Git collaboration rules

1. Before starting, inspect status and remotes, then `git fetch origin` and `git pull --ff-only` on the working branch. If histories diverge, inspect and reconcile first. An empty repository has nothing to pull; fetch before its first commit.
2. Commit and push all completed changes with descriptive commit messages. Use `codex/` for new Codex branches; push the branch and communicate it. Never include another developer's unfinished work.
3. Never force-push, rewrite shared history or overwrite another developer's changes.
4. If a push is rejected, fetch, inspect incoming changes and reconcile before retrying; rerun relevant checks after reconciliation.
5. For conflicts, inspect both versions, their common ancestor and commit history. Resolve automatically only when both changes can safely coexist.
6. If changes contradict each other or intended behavior is unclear, stop and ask the developer. Never arbitrarily select one version or discard work.
7. Run relevant tests before pushing, review the staged diff, and never commit secrets or local `.env` files.
