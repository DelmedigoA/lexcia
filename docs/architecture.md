# Lexcia architecture

The website calls its own Lexcia backend on port 8767. Each request carries the browser conversation UUID. The backend validates requests with Pydantic, ranks local knowledge with BM25, runs a retrieve → answer LangGraph, and translates model chunks into SSE status/item/delta/final events. The scoped prompt answers only from reviewed Lexcia information. No ArchiveLens imports, process, corpus, configuration, or server calls are required.

Sessions are isolated in memory, limited to 128 idle/active entries and ten completed turns per session. Restarting the backend loses its conversation context; on Vercel, a new function instance may also start without earlier turns. Browser transcripts remain local and older ones are read-only. Only completed turns enter backend history. Concurrent requests in the same session are rejected, and cancellation releases its lock. There is no account system or durable server history.

The existing launcher, modal, pinning, resizing, keyboard navigation, saved browser transcripts, and React generative-UI renderer are adapted from the prior local demo. The floating panel anchors to the draggable launcher using viewport-constrained placement that prefers the launcher below the panel’s bottom-left corner; it recalculates on opening, size changes, viewport changes, and unpinning. Pinned mode keeps its left-edge dock. Rich response rendering is available in the frontend but this backend currently produces sourced text only. Sources open the project's reviewed knowledge records. Product positioning, branding and planned pricing are traceable to the reviewed Google Drive document, while implemented demo behavior is traceable to the local prototype. Unknown commercial details are explicitly recorded.

ArchiveLens informed the separation of knowledge, prompts, retrieval, graph, streaming, and UI. Sefaria and assistant-ui remain design references. The backend is a new implementation.

Conversation messages follow the layout and action-bar patterns in [assistant-ui's thread component](https://github.com/assistant-ui/assistant-ui/blob/main/packages/ui/src/components/react/assistant-ui/elements/thread.aui.tsx), using the existing DOM/SSE conversation controller. User messages are compact right-aligned bubbles; assistant replies render Markdown with inline code and copyable code blocks. Completed answers provide copy and helpful/unhelpful controls. Feedback is saved on the turn in local browser transcripts, with mutually exclusive choices and removal by clicking the selected choice; it is not submitted to a backend or used to train the model. Copying removes internal source markers. A waiting indicator covers the first streamed text, the composer grows with drafts, and a jump-to-latest control appears when the reader scrolls away from the bottom. Source links, rich response rendering and existing frame controls retain their prior behavior.
